# Internationalization (i18n)

Gozzi provides built-in support for multilingual websites with automatic language detection, translation management, and language-aware URL generation.

## Configuration

### Basic Setup

Configure languages in `config.toml`:

```toml
[languages]
default = "en"

[languages.en]
name = "English"
weight = 1

[languages.fr]
name = "Français"
weight = 2

[languages.es]
name = "Español"
weight = 3
```

### Translation Files

Create translation files in `data/i18n/` directory:

**data/i18n/en.toml:**
```toml
tagline = "Welcome to our site"

[section]
about = "About Us"
contact = "Contact"

[greeting]
hello = "Hello"
welcome = "Welcome"
```

**data/i18n/fr.toml:**
```toml
tagline = "Bienvenue sur notre site"

[section]
about = "À Propos"
contact = "Contact"

[greeting]
hello = "Bonjour"
welcome = "Bienvenue"
```

## Content Organization

Organize content by language using subdirectories:

```
content/
├── en/
│   ├── _index.md
│   └── about.md
├── fr/
│   ├── _index.md
│   └── about.md
└── es/
    ├── _index.md
    └── about.md
```

### Language Detection

Gozzi automatically detects the language for each content file from:

1. **Frontmatter** (highest priority):
   ```toml
   +++
   title = "About"
   language = "en"
   +++
   ```

2. **File suffix**:
   ```
   about.en.md  → English
   about.fr.md  → French
   ```

3. **Directory structure**:
   ```
   content/en/about.md → English
   content/fr/about.md → French
   ```

4. **Site default** (fallback)

## Template Functions

### i18n

Translate keys to the current language:

```html
{{ i18n "greeting.hello" .Page.Config }}
{{ i18n "section.about" .Page.Config }}
```

The function automatically uses the page's language and falls back to the default language if a translation is missing.

### langURL

Generate language-specific URLs:

```html
<!-- Switch to French version of current page -->
<a href="{{ langURL "fr" .Page }}">Français</a>

<!-- Switch to English version -->
<a href="{{ langURL "en" .Page }}">English</a>

<!-- Using with explicit path -->
<a href="{{ langURL "es" "/about/" }}">Español</a>
```

### currentLang

Get the current language code:

```html
<html lang="{{ currentLang .Page }}">
```

## Example Templates

### Language Switcher

```html
{{ if .Site.Config.i18n_enabled }}
<nav class="language-switcher">
    {{ range .Site.Config.languages }}
    <a href="{{ langURL .code $.Page }}"
       class="{{ if eq .code (currentLang $.Page) }}active{{ end }}">
        {{ .name }}
    </a>
    {{ end }}
</nav>
{{ end }}
```

### Multilingual Navigation

```html
<nav>
    <a href="{{ langURL (currentLang .Page) "/" }}">
        {{ i18n "nav.home" .Page.Config }}
    </a>
    <a href="{{ langURL (currentLang .Page) "/about/" }}">
        {{ i18n "nav.about" .Page.Config }}
    </a>
    <a href="{{ langURL (currentLang .Page) "/contact/" }}">
        {{ i18n "nav.contact" .Page.Config }}
    </a>
</nav>
```

### Complete Example

```html
<!DOCTYPE html>
<html lang="{{ currentLang .Page }}">
<head>
    <title>{{ .Page.Config.title }}</title>
</head>
<body>
    <header>
        <h1>{{ i18n "site.title" .Page.Config }}</h1>

        <!-- Language switcher -->
        {{ if .Site.Config.i18n_enabled }}
        <nav class="language-switcher">
            {{ range .Site.Config.languages }}
            <a href="{{ langURL .code $.Page }}">{{ .name }}</a>
            {{ end }}
        </nav>
        {{ end }}
    </header>

    <main>
        {{ .Page.Content }}
    </main>

    <footer>
        <p>{{ i18n "footer.copyright" .Page.Config }} {{ date "2006" now }}</p>
    </footer>
</body>
</html>
```

## URL Structure

Gozzi generates language-specific URLs automatically:

- English: `/en/`, `/en/about/`, `/en/blog/post1/`
- French: `/fr/`, `/fr/about/`, `/fr/blog/post1/`
- Spanish: `/es/`, `/es/about/`, `/es/blog/post1/`

## Site Config Variables

Access i18n configuration in templates:

```html
<!-- Check if i18n is enabled -->
{{ if .Site.Config.i18n_enabled }}
  <!-- multilingual content -->
{{ end }}

<!-- List all languages -->
{{ range .Site.Config.languages }}
  <option value="{{ .code }}">{{ .name }}</option>
{{ end }}

<!-- Get default language -->
{{ .Site.Config.default_language.code }}
{{ .Site.Config.default_language.name }}
```

## Best Practices

1. **Always provide default language translations**: Ensure all translation keys exist in your default language as a fallback.

2. **Use semantic translation keys**: Use descriptive keys like `section.about` instead of generic keys like `text1`.

3. **Organize translations hierarchically**: Group related translations under common prefixes.

4. **Keep URLs consistent**: Use the same content structure across all languages.

5. **Test all languages**: Verify that translations work correctly for all configured languages.

## Notes

- If i18n is not configured (only one language), all i18n functions gracefully fall back to default behavior.
- Translation keys support nested structures using dot notation (e.g., `section.contact`).
- Missing translations will return the translation key itself, preventing broken pages.
- Language weights determine the order in which languages appear in language lists (lower weight = higher priority).
